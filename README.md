# WMS 仓库管理小程序

面向仓库操作人员的手机端仓储管理系统，使用**原生微信小程序语法**开发（WXML + WXSS + JS + JSON），不依赖 uni-app 等框架。

当前为**纯前端演示版本**：所有数据均为本地模拟，通过 `wx.setStorageSync` 持久化，不请求后端接口。

## 功能说明

### 首页

- **仓库概览**：今日入库单数、今日出库单数、在库商品总量、库存预警项数（均由数据层实时统计）。
- **扫一扫**：`wx.scanCode` 识别条形码 / 二维码，识别后可选「扫码入库 / 扫码出库 / 查询库存」，并携带条码跳到对应页面自动匹配商品。
- **快捷操作**：入库、出库、库存查询、**BOM 维护**、商品管理、操作日志六个入口（三列两行）。BOM 维护是独立入口，不需要先建生产任务就能进去新增机型版本。
- **生产任务**：多个任务同时存在时**同等级平铺**，不再只显示一个。每张卡显示优先级序号、机型版本、计划台数、交付日期与剩余天数、进度条，以及「最多可做台数 / 缺料种数 / 做完预警种数」；逾期的卡片左边条与天数标红，3 天内标橙。卡片右侧「↑ / ↓」可直接手动调整优先级，点击卡片进入该任务的齐套分析页。没有进行中任务时，**没有 BOM 版本会引导去「BOM 维护」**，已有 BOM 才引导去新建任务。
- **优先级规则**：默认按**交付日期由早到晚**自动排序（同一天按创建时间），手动调整后以手动顺序为准，新任务仍按交付日期插到对应位置；任务页「按交付日期重排」可一键恢复自动顺序。顶部会汇总「N 个任务已逾期 / N 个任务缺料」。
- **最近操作**：取最新 5 次「操作」（不是 5 条记录）。生产报工一次会按物料写十几条领料记录，首页把它们按「一次报工」合并成一条蓝色「领料」卡（显示报工台数与物料种数），点开弹层可看逐项物料明细，右上「日志」直达日志页的领料筛选，保证与顶部「今日出库 N 单」口径一致。
- **用户区**：未登录时显示「游客 · 点击登录」并跳转登录页；已登录时点击可「切换账号」或「重置演示数据」。
- **下拉刷新**：重新加载概览与记录。

### 生产任务页（物料齐套分析）

面向「这个版本要投 20 台，料够不够」的场景，是生产与仓库之间的核心衔接页：

- **任务卡**：显示版本号、任务单号、计划台数、已完工台数、交付日期（点击可直接选日期修改）、进度条与齐套摘要；「切换」打开任务列表弹层（按优先级排列，带序号、交付日期与「↑ / ↓」，可切换、可新建、可逐个删除，底部可「按交付日期重排」）；「⋯」提供「结束任务 / 删除任务 / 维护 BOM」。
- **交付日期**：新建任务必填（默认 7 天后），是优先级排序的依据；改日期后该任务会重新按日期插到对应位置。老数据迁移时按「创建时间 + 7 天」自动补齐。改完日期返回首页会立即同步（首页订阅了数据变化，`onShow` 时还会按本地缓存回读一次）。
- **新建任务**：机型版本下拉来自 BOM 维护页的版本列表；一个版本都没有时会提示先去 BOM 维护，弹层里也有「＋ 去 BOM 维护新增版本」的直达入口，不用退出再绕一圈。
- **结束任务**：提前收工，未报工部分不再扣料，任务转为「已完成」保留在列表里。
- **删除任务**：只删除任务本身，已报工产生的库存扣减与「领料」记录属于历史流水，不会回滚（有报工时会先提示已报工台数与保留的记录数）。
- **齐套分析**：按 `单台用量 × 计划台数` 逐项比对物料库存，每种物料给出「单台用量 / 需求 / 库存 / 缺口或做完剩余」，并按状态分三类：
  - `缺料`（红）：库存小于需求，`缺口 = 需求 - 库存`，计入采购清单；
  - `做完预警`（橙）：料够做，但做完这一单后剩余量 ≤ 安全库存（正好用完也算），需要提前补货；
  - `充足`（绿）：做完后仍有充足余量。
- **最多可做台数**：`min(floor(库存 / 单台用量))`，即不考虑采购的情况下当前物料能支撑几台，便于判断要不要分批投产。
- **采购清单**：汇总全部缺料项与估算金额，支持一键复制成文本发给采购。
- **报工**：按实际完工台数一次性扣减各物料库存；**每种物料单独生成一条「领料」记录**（标题为物料名，数量为 `单台用量 × 台数`，备注自动写「生产任务领用 · 版本 × 台数」），日志里能逐条看到少了哪些料；任一物料不足时整单拒绝，避免出现报了一半的中间状态。
- **筛选**：全部 / 缺料 / 做完预警 / 充足，标签上直接带数量。
- 点击物料可「去补料入库」（跳到入库页并自动选中该物料）或「查看物料库存」。

### BOM 维护页

> 数据顺序是「先 BOM、后任务」：BOM（机型版本 + 物料清单）是主数据，生产任务只是引用它。首页快捷操作里有独立入口，任务页「⋯」里也有一个快捷入口。

- 按机型版本维护物料清单（如 V3.1 / V3.0），版本以胶囊切换，可新增、改名、删除（有进行中任务引用的版本不允许删除）。
- 添加物料：搜索物料名称 / SKU / 条码后选择，填写单台用量；点击已有物料可改用量或移除。
- **粘贴导入**：支持从 Excel 直接复制「物料编码 + 单台用量」两列粘贴，每行一条；也兼容 `编码,名称,规格,数量` 这种多列格式（取首列编码与末列数字）。已存在的物料更新用量，新物料自动追加，匹配不到的编码会在导入结果中列出。
- 物料不足时先去「商品管理」新增物料档案，再回到这里加入 BOM。
- **用该版本下任务**：版本卡上的按钮会带着版本号跳到生产任务页，自动打开新建弹层并选中这个版本，不用再手动挑机型。

### 登录页

- 工号 + 密码登录，演示密码统一为 `123456`，支持密码显示 / 隐藏。
- 内置演示工号：`admin`（张伟 · 仓管员）、`lina`（李娜 · 仓管员）、`wangqiang`（王强 · 主管），点一下自动填入。
- 登录态写入 `utils/store.js`，登录成功后返回上一页或重启到首页；支持「退出登录」与「暂不登录，先逛逛」。
- 演示版不强制登录，未登录也可以浏览首页与各功能页。

### 入库页

- 支持扫码（`?code=` 参数进入时自动匹配商品）与关键词搜索（名称 / SKU / 条码）。
- 条码匹配失败时清空已选商品并转为搜索，避免误提交上一件商品。
- 选中商品后展示当前库存、库存状态与默认库位；数量支持步进器与 +10 / +50 / +100 快捷加量。
- 提交后写入记录、累加库存，页面顶部展示本次入库单号与最新库存，可继续录入下一单。
- 顶部「入库 / 出库」分段切换可在两个页面间直接跳转。

### 出库页

- 与入库页同构，额外做**库存校验**：超出可出库数量时拦截提交并提示剩余数量。
- 「出库后剩余」实时计算，超出库存时标红；`全部` 快捷键可一键填入全部库存。
- 出库成功后扣减库存，并展示单号与剩余库存。

### 库存查询页

- 顶部汇总商品种类、库存总量、预警商品数。
- 状态筛选：全部 / 正常 / 预警 / 缺货；支持名称、SKU、条码搜索。
- 列表按「缺货 → 预警 → 正常」排序，便于优先处理异常；左侧色条对应库存状态。
- 点击商品可选择「入库该商品 / 出库该商品 / 查看库存详情」，前两项会带条码跳转并自动选中商品；库存详情含分类、供应商、库位、单价与库存金额。

### 商品管理页

- 搜索 + 分类筛选，分类来自「分类管理」页，可自由增删改；搜索支持名称 / SKU / 条码 / **供应商**。
- 物料与商品共用同一张库存表：机芯物料只是分类不同，生产领料与普通出入库走同一套库存，不额外维护两套账。
- 每个商品档案含**供应商**字段，新增 / 编辑弹层里可填写，列表卡片直接展示；未填写的显示浅色的「未填写，点编辑补充」。
- 右下角「＋」打开底部弹层新增商品；点击商品可编辑或删除。
- 表单校验：名称、SKU 必填，SKU 不可重复，库存与安全库存不能为负，供应商名称最长 40 字。
- 删除有二次确认，删除后库存与列表同步刷新。
- 分类条右侧的「分类管理」可进入分类维护页。

### 分类管理页

用于替换掉不需要的分类、补上自己公司的分类，商品与机芯物料共用同一套分类：

- **新增分类**：底部「＋ 新增分类」输入名称即可，新增后立刻出现在商品管理的筛选条与编辑弹层的分类选择里。
- **重命名分类**：会把该分类下所有商品、物料同步改成新名称，不会出现「商品还挂在旧分类上」的情况。
- **删除分类**：分类下没有商品时直接删除；仍有商品时会提示数量，确认后这些商品自动迁到「未分类」，库存与记录都不受影响。
- **未分类**：系统保留的兜底分类，不能删除或重命名，保证任何商品都有归属。
- 重名、空名称、超过 12 个字都会被拦下；分类名称不可重复。
- 删除是幂等的：删除后商品管理页的筛选会自动回退到「全部」，不会停在已删除的分类上。

### 操作日志页

- 顶部统计全部记录、入库单、出库单、领料条数；筛选项为 全部 / 入库 / 出库 / **领料**，其中「出库」只统计普通出库，领料单独成类，互不重复计数。
- 记录按日期分组（今天 / 昨天 / 具体日期），展示类型、商品、SKU、规格、时间、操作人、库位与数量；有备注时额外显示一行备注（生产领料会显示「生产任务领用 · V3.1 × 3 台」），领料标识用蓝色与普通出库区分。
- 点击记录查看完整详情（含单号、关联生产任务与备注）；支持下拉刷新。

## 数据层 `utils/store.js`

所有页面共用一份数据，读写都通过这个模块，页面之间不需要互相传数据：

| 方法 | 说明 |
| --- | --- |
| `listCategories()` | 分类列表，带每个分类下的商品数量与是否可删除 |
| `categoryNames()` | 分类名称数组，供筛选条与下拉选择使用 |
| `getDefaultCategory()` | 新增商品时的默认分类（第一个非「未分类」的分类） |
| `addCategory(name)` | 新增分类，重名 / 空名 / 超长会被拒绝 |
| `renameCategory(id, name)` | 重命名分类，同步更新该分类下所有商品与物料 |
| `removeCategory(id, { moveTo })` | 删除分类，其下商品迁到 `moveTo` 或「未分类」 |
| `listGoods({ keyword, category, status })` | 查询商品，按 keyword 模糊匹配名称 / SKU / 条码 / 供应商，`status` 取 `all / normal / warning / empty` |
| `getGoods(id)` | 按 id 查商品（带 `status` / `statusText` 展示字段） |
| `findGoodsByCode(code)` | 按条码 / SKU / 商品编号匹配，供扫码使用 |
| `saveGoods(payload)` | 新增（无 `id`）或更新商品，含必填与 SKU 重复校验 |
| `removeGoods(id)` | 删除商品 |
| `listRecords({ type, limit })` | 查询出入库记录，按时间倒序；返回时按当前时间重算 `time`（隔天不会仍显示旧相对时间） |
| `listRecentOps({ limit })` | 首页「最近操作」：按一次操作聚合，同批报工（`taskId + createdAt` 相同）的领料记录合成一条，物料明细在 `lines` 里 |
| `isPickRecord(record)` | 判断是否生产领料记录（`type === 'out'` 且有 `taskId`） |
| `addRecord({ type, goodsId, quantity, location, remark, operator })` | 新增记录并同步库存，出库时校验库存是否充足 |
| `getOverview()` | 首页概览统计（今日入库 / 出库 / 在库总量 / 预警数） |
| `subscribe(handler)` | 订阅数据变化，返回取消订阅函数；任何页面写库后立即回调，首页靠它做到跨页实时同步 |
| `reload()` | 强制按本地缓存重新读一遍数据（页面 `onShow` 调用），避免读到本次启动时缓存的旧副本 |
| `getUser()` / `setUser()` / `clearUser()` | 登录态读写 |
| `resetDemoData()` | 恢复初始演示数据 |
| `listBoms()` / `getBom(id)` | BOM 版本列表 / 详情（物料行已补上名称、库存等展示字段） |
| `saveBom({ id, version, name, remark })` | 新增（无 `id`）或修改 BOM 版本，版本号不可重复 |
| `removeBom(id)` | 删除版本，有进行中任务引用时拒绝 |
| `saveBomItem({ bomId, goodsId, qty })` | 新增 / 修改某物料的单台用量（upsert） |
| `removeBomItem(bomId, goodsId)` | 从 BOM 移除物料 |
| `importBomText(bomId, text)` | 粘贴导入 BOM 文本，返回新增 / 更新 / 未匹配项 |
| `analyzeTask({ bomId, planQty })` | **齐套分析核心**：返回每种物料的需求、缺口、做完剩余、可支持台数、状态，以及缺料种数、采购金额、最多可做台数 |
| `listTasks()` / `getTaskAnalysis(id)` | 任务列表（进行中在前，再按优先级）/ 单个任务的齐套详情 |
| `getTaskBoard()` | 首页任务看板：全部进行中任务，带 `priority` / `canMoveUp` / `canMoveDown` 与逾期、缺料汇总 |
| `getCurrentTask()` | 优先级最高的进行中任务（默认即交付日期最早那条） |
| `moveTask(taskId, 'up' \| 'down')` | 手动调整优先级，按新顺序重分配任务权重，返回 `{ ok, position }` |
| `resetTaskOrder()` | 恢复按交付日期自动排序，覆盖手动顺序 |
| `setTaskDueDate(taskId, 'YYYY-MM-DD')` | 修改交付日期，并把任务重新按日期插队 |
| `dueInfoOf('YYYY-MM-DD')` | 交付日期展示信息：`dueLevel`（overdue / today / soon / normal / none）、`dueTip`、`dueDays` |
| `saveTask({ bomId, planQty, dueDate, remark, operator })` | 新建生产任务，`dueDate` 缺省为 7 天后 |
| `reportTask(taskId, qty)` | 报工：按 BOM 扣减物料库存，每种物料写一条「领料」记录；返回 `{ task, records, recordCount, record, lines }`，物料不足时整单拒绝 |
| `finishTask(taskId)` | 手动结束任务（未报工部分不扣料） |
| `removeTask(taskId)` | 删除任务，返回 `recordCount`；库存与领料记录不回滚 |

- 商品状态规则：库存 `0` 为「缺货」，`≤ 安全库存` 为「库存预警」，否则「正常」。
- 齐套状态规则：`需求 > 库存` 为「缺料」，否则 `库存 - 需求 ≤ 安全库存` 为「做完预警」，其余为「充足」。
- 分类规则：分类存在 `state.categories`（不再写死在代码里），有商品引用的分类删除时商品迁到「未分类」；「未分类」为系统保留分类，不可删除、不可重命名。
- 数据落地在本地缓存键 `wms_demo_state_v1`，登录态在 `wms_demo_session_v1`；`schemaVersion` 用于存量数据迁移（当前 3）。
- 记录上限 `MAX_RECORDS = 2000`：领料按物料逐条写入后增长很快，超出时自动丢弃最早的记录（按 `createdAt` 倒序保留），避免写爆小程序单 key 1MB 限制导致「提示成功但重启后丢失」。
- 初始数据：9 个分类（含「未分类」）、10 个演示商品 + 15 个机芯物料（共 25 种，含 4 个预警 / 1 个缺货）、5 条历史出入库记录、2 个 BOM 版本（V3.1 / V3.0）、1 个进行中的任务（V3.1 × 20 台）；种子商品的供应商按分类预填（映射见 `SEED_SUPPLIERS`），可随时改。
- 手机端已有旧缓存时会自动迁移：补齐机芯物料、BOM、任务与分类表（商品上用到的历史分类会被保留），原有商品与出入库记录全部保留（已存在的物料不覆盖用户改过的库存）。

## 演示流程建议

1. 首页点击右上角用户区 → 「登录」→ 点演示工号 `admin` → 自动填入密码 → 登录。
2. 首页「入库 →」扫码或搜索 `无线蓝牙耳机`，数量填 20，确认入库，顶部出现单号。
3. 回首页看「今日入库」+1 与最近操作列表已更新。
4. 回到首页「生产任务」列表（`V3.1 × 20 台`）→ 点任务卡进入齐套分析：
   - 看到「最多可做 4 台」「缺料 6 种」「做完预警 2 种」，物料列表里红色为缺料（如精密齿轮组缺 2 套）、橙色为做完会低于安全库存（如磁编码器正好用完）；
   - 点底部「生成采购单」，核对缺口与金额后「复制」，可直接发给采购；
   - 物料到货后正常入库，再回本页缺口会自动消失。
5. 点「报工」输入完工台数（如 3 台），系统按 BOM 扣减全部物料库存，并为每种物料生成一条「领料」记录（备注「生产任务领用」），任务进度推进。
6. 进入「库存查询」，筛选「预警」可以看到做完这一单后进入预警的物料，点击可直接补货或出库。
7. 进入「操作日志」，切到「领料」可以看到本次报工逐条扣减的物料（每行一个物料，备注为「生产任务领用 · V3.1 × 3 台」）。
8. 需要调整分类：商品管理页分类条右侧「分类管理」→ 删除不需要的分类（如「办公耗材」）、新增自己的分类（如「机芯外壳」），返回商品管理即可在筛选条和新增商品的分类选择里看到。
9. 需要新增/调整机型 BOM（**不需要先建任务**）：首页快捷操作 →「BOM 维护」→ 顶部「＋ 新版本」填版本号与名称 → 添加物料或粘贴导入；维护完点「用该版本下任务」直接带去新建生产任务。任务页右上角「⋯」→「维护 BOM」也能进；新建任务弹层里也有「＋ 去 BOM 维护新增版本」。
10. 任务建错了或想清理历史：任务卡右上角「切换」打开任务列表，逐行「删除」；或「⋯」→「删除任务」。只想提前收工、保留记录则选「⋯」→「结束任务」。
10. 想恢复初始数据：首页点击用户区 → 「重置演示数据」。

## 二次开发约定

- 每个页面放在 `miniprogram/pages/<页面名>/` 下，文件统一命名为 `index.js / index.json / index.wxml / index.wxss`。
- 数据统一走 `utils/store.js`，不要在页面里再写一份独立的模拟数据；接真实接口时只替换该文件内部实现，保持方法签名与字段结构不变，页面代码基本不用改。
- 颜色、圆角等主题变量统一定义在 `miniprogram/app.wxss` 的 `page` 选择器中，页面内通过 `var(--xxx)` 引用。
- 出入库两页共用 `app.wxss` 里的表单样式，强调色由容器上的 `.accent-in`（绿）/ `.accent-out`（橙）切换。
- 新增页面步骤：新建目录与四个文件 → 在 `app.json` 的 `pages` 中登记路径 → 若需要从首页进入，把路径加入 `pages/index/index.js` 的 `READY_PAGES`。
- 生产相关算法（需求、缺口、可支持台数、预警判定、报工扣料）全部集中在 `utils/store.js` 的 `analyzeBom` / `reportTask` 里，页面只负责展示；调整计算口径时改这一处即可，不要在各页面里重算。
- 分类不再写死在代码里：初始分类是 `utils/store.js` 中的 `SEED_CATEGORIES`，运行期以 `state.categories` 为准，页面通过 `listCategories()` / `categoryNames()` 读取。要改「出厂分类」，改 `SEED_CATEGORIES` 并重置演示数据；日常增减请在「分类管理」页操作。

## 常见问题

- **提示 `module 'xxx.js' is not defined`**：通常是新增文件后，开发者工具仍在使用旧的编译文件列表。执行「工具 → 清除缓存 → 全部清除」，然后重新编译。
- **提示找不到旧页面（如 `pages/example/index`）**：说明工具仍在用旧项目的编译缓存。清除缓存，或关闭项目后重新导入 `E:\Wx_miniprogram`。
- **JSON 报错 `Unexpected token` 且开头是一个看不见的字符**：文件被保存成了带 BOM 的 UTF-8。请将 `app.json` 等 JSON 文件另存为 **UTF-8（无 BOM）**；本项目的 JSON 文件都不要带 BOM。
- **`.js` 文件开头出现 `podlp` 之类的乱码**：文件被其他程序以二进制方式覆盖了（本机装有文件加密 / 防护软件时偶发）。可直接从 Git 恢复对应文件，或重新保存为 UTF-8 文本后再编译。
- **改了数据但页面没变化**：数据存在本地缓存里，可在首页用户区「重置演示数据」，或在开发者工具「清缓存 → 清除数据缓存」后重新编译。
- **手机上看不到机芯物料 / BOM**：手机本地缓存里还是旧版数据。本版已带自动迁移（进入小程序后补齐物料、BOM 与任务，原记录不丢）；若仍不对，在首页用户区「重置演示数据」即可恢复完整初始数据。
- **齐套分析里显示「物料已删除」**：BOM 引用的物料在商品管理里被删掉了，去「BOM 维护」重新选择物料，或重新新增该物料档案。
- **分类删不掉 / 改不了名**：`未分类` 是系统保留的兜底分类，不能删除也不能改名，其余分类都可以自由增删改。
- **新增分类后商品管理里看不到**：分类管理页保存后返回商品管理即可（页面 `onShow` 会重新读取分类表）；若仍没有，检查是否停在旧分类筛选上，点「全部」再看。
