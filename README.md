# WMS 仓库管理小程序

面向仓库操作人员的手机端仓储管理系统，使用**原生微信小程序语法**开发（WXML + WXSS + JS + JSON），不依赖 uni-app 等框架。

当前为**纯前端演示版本**：所有数据均为本地模拟，通过 `wx.setStorageSync` 持久化，不请求后端接口。

## 功能说明

### 首页

- **仓库概览**：今日入库单数、今日出库单数、在库商品总量、库存预警项数（均由数据层实时统计）。
- **扫一扫**：`wx.scanCode` 识别条形码 / 二维码，识别后可选「扫码入库 / 扫码出库 / 查询库存」，并携带条码跳到对应页面自动匹配商品。
- **快捷操作**：入库、出库、库存查询、商品管理、操作日志五个入口。
- **最近操作**：取最新 5 条出入库记录，点击查看详情。
- **用户区**：未登录时显示「游客 · 点击登录」并跳转登录页；已登录时点击可「切换账号」或「重置演示数据」。
- **下拉刷新**：重新加载概览与记录。

### 登录页

- 工号 + 密码登录，演示密码统一为 `123456`，支持密码显示 / 隐藏。
- 内置演示工号：`admin`（张伟 · 仓管员）、`lina`（李娜 · 仓管员）、`wangqiang`（王强 · 主管），点一下自动填入。
- 登录态写入 `utils/store.js`，登录成功后返回上一页或重启到首页；支持「退出登录」与「暂不登录，先逛逛」。
- 演示版不强制登录，未登录也可以浏览首页与各功能页。

### 入库页

- 支持扫码（`?code=` 参数进入时自动匹配商品）与关键词搜索（名称 / SKU / 条码）。
- 条码匹配失败时清空已选商品并转为搜索，避免误提交上一件商品。
- 选中商品后展示当前库存、库存状态与默认库位；数量支持步进器与 +10 / +50 / +100 快捷加量。
- 提交后写入记录、累加库存，页面顶部展示本次入库单号与最新库存，可继续录入下一单。
- 顶部「入库 / 出库」分段切换可在两个页面间直接跳转。

### 出库页

- 与入库页同构，额外做**库存校验**：超出可出库数量时拦截提交并提示剩余数量。
- 「出库后剩余」实时计算，超出库存时标红；`全部` 快捷键可一键填入全部库存。
- 出库成功后扣减库存，并展示单号与剩余库存。

### 库存查询页

- 顶部汇总商品种类、库存总量、预警商品数。
- 状态筛选：全部 / 正常 / 预警 / 缺货；支持名称、SKU、条码搜索。
- 列表按「缺货 → 预警 → 正常」排序，便于优先处理异常；左侧色条对应库存状态。
- 点击商品可选择「入库该商品 / 出库该商品 / 查看库存详情」，前两项会带条码跳转并自动选中商品。

### 商品管理页

- 搜索 + 分类筛选（数码配件 / 音频设备 / 智能穿戴 / 办公耗材）。
- 右下角「＋」打开底部弹层新增商品；点击商品可编辑或删除。
- 表单校验：名称、SKU 必填，SKU 不可重复，库存与安全库存不能为负。
- 删除有二次确认，删除后库存与列表同步刷新。

### 操作日志页

- 顶部统计全部记录、入库单、出库单数量，支持按类型筛选。
- 记录按日期分组（今天 / 昨天 / 具体日期），展示类型、商品、SKU、规格、时间、操作人、库位与数量。
- 点击记录查看完整详情（含单号与备注）；支持下拉刷新。

## 数据层 `utils/store.js`

所有页面共用一份数据，读写都通过这个模块，页面之间不需要互相传数据：

| 方法 | 说明 |
| --- | --- |
| `listGoods({ keyword, category, status })` | 查询商品，按 keyword 模糊匹配名称 / SKU / 条码，`status` 取 `all / normal / warning / empty` |
| `getGoods(id)` | 按 id 查商品（带 `status` / `statusText` 展示字段） |
| `findGoodsByCode(code)` | 按条码 / SKU / 商品编号匹配，供扫码使用 |
| `saveGoods(payload)` | 新增（无 `id`）或更新商品，含必填与 SKU 重复校验 |
| `removeGoods(id)` | 删除商品 |
| `listRecords({ type, limit })` | 查询出入库记录，按时间倒序 |
| `addRecord({ type, goodsId, quantity, location, remark, operator })` | 新增记录并同步库存，出库时校验库存是否充足 |
| `getOverview()` | 首页概览统计（今日入库 / 出库 / 在库总量 / 预警数） |
| `getUser()` / `setUser()` / `clearUser()` | 登录态读写 |
| `resetDemoData()` | 恢复初始演示数据 |

- 商品状态规则：库存 `0` 为「缺货」，`≤ 安全库存` 为「库存预警」，否则「正常」。
- 数据落地在本地缓存键 `wms_demo_state_v1`，登录态在 `wms_demo_session_v1`。
- 初始数据：10 个商品（含 3 个预警、1 个缺货）、5 条历史出入库记录，记录时间相对当前时间生成。

## 运行方式

1. 打开微信开发者工具，选择「导入项目」。
2. 项目目录选择本仓库根目录 `Wx_miniprogram`。
3. AppID 使用 `project.config.json` 中的 `wx00025c1841c755b4`，或替换为你自己的 AppID。
4. 编译后即可在模拟器 / 真机预览。演示账号 `admin` / `123456`。

## 演示流程建议

1. 首页点击右上角用户区 → 「登录」→ 点演示工号 `admin` → 自动填入密码 → 登录。
2. 首页「入库 →」扫码或搜索 `无线蓝牙耳机`，数量填 20，确认入库，顶部出现单号。
3. 回首页看「今日入库」+1 与最近操作列表已更新。
4. 进入「库存查询」，筛选「预警」可以看到库存低于安全线的商品，点击可直接补货或出库。
5. 进入「操作日志」，按「入库 / 出库」筛选并点开记录查看详情。
6. 想恢复初始数据：首页点击用户区 → 「重置演示数据」。

## 二次开发约定

- 每个页面放在 `miniprogram/pages/<页面名>/` 下，文件统一命名为 `index.js / index.json / index.wxml / index.wxss`。
- 数据统一走 `utils/store.js`，不要在页面里再写一份独立的模拟数据；接真实接口时只替换该文件内部实现，保持方法签名与字段结构不变，页面代码基本不用改。
- 颜色、圆角等主题变量统一定义在 `miniprogram/app.wxss` 的 `page` 选择器中，页面内通过 `var(--xxx)` 引用。
- 出入库两页共用 `app.wxss` 里的表单样式，强调色由容器上的 `.accent-in`（绿）/ `.accent-out`（橙）切换。
- 新增页面步骤：新建目录与四个文件 → 在 `app.json` 的 `pages` 中登记路径 → 若需要从首页进入，把路径加入 `pages/index/index.js` 的 `READY_PAGES`。

## 常见问题

- **提示 `module 'xxx.js' is not defined`**：通常是新增文件后，开发者工具仍在使用旧的编译文件列表。执行「工具 → 清除缓存 → 全部清除」，然后重新编译。
- **提示找不到旧页面（如 `pages/example/index`）**：说明工具仍在用旧项目的编译缓存。清除缓存，或关闭项目后重新导入 `E:\Wx_miniprogram`。
- **JSON 报错 `Unexpected token` 且开头是一个看不见的字符**：文件被保存成了带 BOM 的 UTF-8。请将 `app.json` 等 JSON 文件另存为 **UTF-8（无 BOM）**；本项目的 JSON 文件都不要带 BOM。
- **`.js` 文件开头出现 `podlp` 之类的乱码**：文件被其他程序以二进制方式覆盖了（本机装有文件加密 / 防护软件时偶发）。可直接从 Git 恢复对应文件，或重新保存为 UTF-8 文本后再编译。
- **改了数据但页面没变化**：数据存在本地缓存里，可在首页用户区「重置演示数据」，或在开发者工具「清缓存 → 清除数据缓存」后重新编译。
